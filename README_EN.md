# Summer

English | [中文](README.md)

The name Summer comes from a similar project I worked on three years ago, when
Llama 2 did not support Chinese. This summer, I am revisiting that work. The goal
is to achieve state-of-the-art results at the lowest possible cost using current
best practices.

Summer is a bilingual Chinese-English, GPT-2 1.5B-class base model with a custom
tokenizer and a pure PyTorch implementation.

It replaces the native vocabulary of `Qwen3-1.7B-Base` (151,643 BBPE tokens) with
a self-trained Piece vocabulary (81,903 tokens), then restores model capabilities
through two-stage continued pretraining. This process is known as ReTok
([arXiv:2410.04335](https://arxiv.org/abs/2410.04335)). The repository covers the
complete workflow from corpus download to Hugging Face publication: vocabulary
surgery, pre-encoding, two-stage pretraining, evaluation, export, and release.
The model and training code in `src/` depend only on torch. The Qwen3 forward
pass, LoRA, Muon/Aurora, and safetensors I/O are all implemented independently
for clarity.

The result is a 1.5B-parameter base model, comparable in size to GPT-2 XL. It is
not instruction-tuned and is not a chat model. Its downstream use is the custom
Chinese-English translation model
[`Interpreter`](https://github.com/Ismantic/Interpreter).

```python
import torch
from model import Qwen3ForCausalLM          # Custom Qwen3, requires only torch
from tokenizer import PieceTokenizerWrapper

tok = PieceTokenizerWrapper(".")
model = Qwen3ForCausalLM.from_pretrained(".", device="cuda", dtype=torch.bfloat16)
ids = tok.encode("机器翻译的基本任务是")
logits = model(torch.tensor([ids], device="cuda"))
```

See `example_load.py` in the release package for a complete greedy-generation
loop. This is a base model: it continues text rather than holding a conversation.
Text after `->` is generated by the model and truncated at the first full stop:

```text
机器翻译的基本任务是 -> 将一种语言的文本翻译成另一种语言的文本.
中文分词的目标是 -> 将一个句子分割成若干个词语,这些词语是句子的基本单位.
深度学习之所以有效,是因为 -> 它能从大量的数据中学习到有用的特征,而这些特征是人类无法通过传统的方法发现的.
```

```bash
cd ReTok && python example_load.py     # Custom forward pass, torch only

```

The release package includes inference code and two examples. Apart from PyTorch
and PieceTokenizer, it has no dependencies: neither transformers nor the
safetensors library is required.

The tokenizer does not use a standard format, so `AutoTokenizer`, Hugging Face
online inference, and an out-of-the-box `vllm serve` setup are not supported.
vLLM can load the weights using its own Qwen3 implementation, but requires
`skip_tokenizer_init=True` and manually encoded IDs. See `example_vllm.py`.

## Performance

WMT22, 1,000 samples, 5-shot, vLLM backend:

| | zh-en BLEU | zh-en COMET | en-zh BLEU | en-zh COMET |
|---|---:|---:|---:|---:|
| Qwen3-1.7B-Base | 22.34 | 0.8122 | 38.34 | 0.8597 |
| Phase 1 | 20.26 | 0.7821 | 35.16 | 0.8276 |
| Phase 2 | 20.46 | 0.7933 | 36.03 | 0.8444 |

| | LAMBADA | PIQA | ARC-C | HellaSwag | CEVAL | GSM8K |
|---|---:|---:|---:|---:|---:|---:|
| Qwen3-1.7B-Base | 0.6513 | 0.7731 | 0.5512 | 0.6705 | 0.6560 | 0.6710 |
| Phase 1 | 0.5674 | 0.7301 | 0.5137 | 0.6375 | 0.6263 | 0.0341 |
| Phase 2 | 0.5768 | 0.7367 | 0.5145 | 0.6389 | 0.6204 | 0.0349 |

LAMBADA and CEVAL use `acc`; PIQA, ARC-C, and HellaSwag use `acc_norm`; GSM8K
uses `exact_match,strict-match`. Shot counts are 0, 5, 25, 10, 5, and 5,
respectively.

## Trade-offs

This is not an improvement where changing the vocabulary simply makes the model
stronger. The full accounting is:

| | |
|---|---|
| Cost | WMT22 zh-en BLEU -1.88 and en-zh BLEU -2.31 |
| Cost | GSM8K drops to about 0.035 and does not recover in either stage |
| Benefit | Vocabulary shrinks from 151,643 to 81,903, a 46% reduction; embedding parameters decrease by 142.9M |
| Benefit | The tokenizer and base model are fully self-owned and do not depend on the Qwen vocabulary |

The greater benefit is independence, not efficiency.

## Architecture

28L / 2048H / 6144I / GQA 16:8 / Head-Dim 128, identical to
Qwen3-1.7B-Base.

| | Qwen3-1.7B-Base | This project |
|---|---:|---:|
| Vocabulary | 151,643 (BBPE) | 81,903 (self-trained Piece) |
| Parameters | 1,720,574,976 | 1,577,147,392 |
| Embeddings | 310.6M | 167.7M |

GPT-2 XL has 1,557,611,200 parameters. The difference is 1.25%, making the models
similar in scale but entirely different in shape. GPT-2 XL has 48 layers with a
width of 1,600, making it deep and narrow. This project reallocates the same
parameter budget using a 2025 architecture.

The two-stage recipe processes 1.2B tokens in about 30 hours on one RTX 4090:

- Phase 1 freezes the transformer and trains only `embed` and `lm_head`: 3,815
  steps, 1B tokens, 25.1 hours.

- Phase 2 applies tie-safe LoRA annealing: q/v use rank-16 low-rank paths,
  `embed` is fully trained, and tied weights keep `lm_head` synchronized: 1,500
  steps, 200M tokens, 5.2 hours.

Embeddings are initialized with mean-of-BBPE. Each new Piece token is passed
through the original Qwen tokenizer, then initialized from the mean of the
corresponding old embeddings. In practice, 66.4% are one-to-one mappings, 32.5%
are many-to-one mappings, and 1.1% fall back to the global mean.

## Code

The repository has four layers organized by data flow:

```text
data/       Download corpora; source.py is the single source of truth
prepare/    Dependencies, vocabulary surgery, pre-encoding, training, evaluation
src/        Model definitions and training loop
save/       Export, upload, and verify the Hugging Face release package
```

Two architectural constraints must be preserved:

- `src/` depends only on torch. Qwen3 forward, LoRA, safetensors I/O, and
  Muon/Aurora are implemented locally instead of using transformers, peft, or
  safetensors.

- `src/` never processes text. Tokenization and text-to-ID conversion happen in
  `prepare/`; `src/` reads only pre-encoded IDs. PieceTokenizer is therefore not
  a dependency of `src/`.

The custom implementation matches transformers layer by layer with a maximum
float32 error of 1.66e-6 and 100% identical argmax results. Its logits match peft
bit for bit.

Each layer has its own README. The repository also contains `deps/` for cloned
C++ dependencies (gitignored), `docs/`, and `test/`.

## Training

Corpora, vocabularies, and base weights are downloaded from Hugging Face and
GitHub. No existing local data is required.

```bash
make deps                  # Clone and build PieceTokenizer
make -C data probe         # Validate the data source registry
make -C prepare status     # Check the output of each pipeline stage
```

| Goal | Time | Starting point | Guide |
|---|---|---|---|
| Evaluate results | Minutes | ReTok model on Hugging Face | [`docs/eval/pipeline.md`](docs/eval/pipeline.md) |
| Two-stage training | About 30 hours plus pre-encoding | Qwen3-1.7B-Base | [`docs/PRETRAIN.md`](docs/PRETRAIN.md) |

Start with evaluation. It provides feedback within minutes and validates the
entire pipeline, including the tokenizer, model, data, and metrics. `make test`
is the regression suite and takes a few minutes.

The only manual step is accepting the terms for the gated `BAAI/CCI3-HQ` dataset
on Hugging Face, then running `huggingface-cli login`.

## Environment

Python 3.11 and torch 2.11. The default setup uses one RTX 4090 (24 GB, BF16).

```bash
uv pip install -r requirements.txt     # Training and evaluation dependencies
```

The C++ dependency
[PieceTokenizer](https://github.com/Ismantic/PieceTokenizer) is cloned and built
by `make deps` and requires CMake plus a C++17 compiler. The 81,903-token
vocabulary and Chinese word segmentation dictionary live under `save/` in that
repository and are not duplicated here.
